# ADR-0005: PIIマスキングの先行実装方針（既定OFFを前提としたopt-inゲート）

## ステータス

Accepted（2026-08-20）

## コンテキスト

`docs/design/01_要件定義.md` FR-SEC-007 はPrompt/Response本文の機微情報マスキングを要求するが、`docs/design/03_基本設計.md` 3.8 の `RegexPiiMaskStrategy` は名称のみで対象PII種別・具体パターンが未定義（`docs/design-review.md` #5, U6, A8 参照）。法務レビューの完了を待つとリリースが止まる懸念があった。

## 決定

汎用パターンで先行実装してよい。理由: `docs/design/01_要件定義.md` NFR-DAT-002 によりPrompt/Response本文の保存は**既定OFF**であり、`docs/design/02_システム仕様.md` 2.18 により本文保存はテナントポリシーでopt-inかつマスキングパイプライン必須。**既定構成ではPIIがAudit Storeに到達しない**ため、法務レビューはopt-in有効化時のゲートであり、リリースそのもののゲートではない。

- `MaskingStrategy` をSPI化し、汎用パターン実装（メールアドレス、電話番号、クレジットカード番号、マイナンバー形式、IPアドレス等）を同梱する。
- **「マスキング設定が明示されていない限り、本文保存opt-inを有効化できない」ガードを設定検証時に強制する。**
- 正規表現ベースのマスキングは**完全ではない**ことを `docs/` に明記し、これをもってコンプライアンス充足を主張してはならない旨を明示する。

## 影響（Consequences）

- **制約**: 本文保存opt-in機能のリリースには、上記ガード実装とドキュメント明記が前提条件となる。ガードなしでopt-inを有効化できる実装は不可。
- **見直す条件**: 法務レビューでマスキング対象PII種別・パターンの追加/変更要求が出た場合、`MaskingStrategy` 実装を差し替える（SPIのため既存呼び出し元への影響なし）。
- **未決定**: 具体的な正規表現パターンの網羅性・地域別PII規制（GDPR等）対応は本ADRの範囲外。実装時に個別定義する。
- **関連**: `docs/design-review.md` #5 / U6 / A8。
