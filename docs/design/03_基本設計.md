# 3. 基本設計

AI Provider Abstraction Platform（APAP）設計書 第3章

インターフェースは言語非依存の疑似コードで定義する。`interface` はSPI/Port、`class` は実装、`<T>` はジェネリクス、`?` はOptionalを表す。

---

## 3.1 パッケージ構成

```
apap
├── apap-api            … 公開契約（OpenAPI/Protobuf、共通DTO、エラーコード）
├── apap-domain         … Domain層（Entity/VO/Aggregate/Domain Service/Event/Port）
├── apap-application    … Application層（UseCase、Command/Query Handler）
├── apap-gateway        … Presentation層（REST/gRPC/SSE Controller、認証フィルタ）
├── apap-execution      … Execution Engine / Retry / Fallback / CB / Streaming
├── apap-routing        … Routing Engine / Policy評価 / Load Balancer
├── apap-prompt         … Prompt Engine / Template / Validation / Optimization
├── apap-context        … Context / Conversation / Session / Memory
├── apap-provider       … Provider Manager / Model Manager / Capability Registry
├── apap-plugin         … Plugin Manager / SPI定義の実行時契約
├── apap-cache          … Cache Engine（SPI + 既定実装）
├── apap-cost           … Cost Engine / Quota
├── apap-observability  … Monitoring / Audit / Tracing
├── apap-infrastructure … Repository実装 / Event Bus / Secret Store / KVS
├── apap-adapter-spi    … Provider Adapter SPI（Adapter開発者向け公開契約）
└── adapters/           … Provider毎の独立Pluginモジュール（別リポジトリ可）
    ├── adapter-example-a
    └── adapter-example-b
```

依存規則: `apap-domain` は他モジュールへ依存しない。`apap-adapter-spi` は `apap-domain` の型のみ参照。`adapters/*` は `apap-adapter-spi` のみに依存（コアへ依存しない）。

### 3.3.2 Provider Adapter SPI（apap-adapter-spi）— 最重要契約

```
// すべてのProvider Pluginが実装する。Capability毎のadapterは
// supports() で申告し、未対応はUNSUPPORTED_CAPABILITYを返す。
interface ProviderAdapter {
    // ライフサイクル
    initialize(config: AdapterConfig, secrets: SecretAccessor): void
    shutdown(): void
    spiVersion(): SemVer

    // 能力申告
    supportedCapabilities(): Set<CapabilityId>
    capabilityConstraints(capabilityId): CapabilityConstraints

    // 認証（抽象化。実装内でapi_key/oauth2/署名等を処理）
    authenticate(): AuthContext
    validateCredential(ref: CredentialRef): ValidationResult

    // 実行（同期）
    execute(request: AdapterRequest): AdapterResponse
        throws AdapterException   // 分類済み: TRANSIENT|RATE_LIMITED|AUTH_ERROR|...

    // 実行（ストリーム）: pull型。next()がブロック/待機
    executeStream(request: AdapterRequest): AdapterStream
    interface AdapterStream {
        next(): AdapterChunk?     // null = 終端
        cancel(): void
    }

    // Tool/Function変換（共通形式 ⇄ Provider固有形式）
    // ※ 実装は execute 内部で行うが、明示変換が必要な場合の公開点
    translateTools(tools: ToolDefinition[]): ProviderToolFormat

    // 管理系
    discoverModels(): DiscoveredModel[]
    healthCheck(): HealthResult          // status, latency, detail
    fetchUsage(period: Period): ProviderUsage?    // Provider側集計（任意対応）
    fetchCost(period: Period): ProviderCost?      // Provider側請求（任意対応）
}

class AdapterRequest {
    capabilityId, modelName, input, params, tools?, outputSchema?,
    timeout: Duration, traceHeaders: Map, authContext: AuthContext
}

class AdapterConfig {
    providerId, endpoints[], rateLimits, regions[], options: Map
}

// Secret値はSecretAccessor経由でのみ取得（値のキャッシュ禁止、都度取得）
interface SecretAccessor {
    resolve(ref: CredentialRef): SecretValue   // 有効期間つき、close()で消去
}
```

### 3.3.3 Execution Engine（apap-execution）

```
interface ExecutionEngine {
    execute(request: CanonicalRequest): CanonicalResponse
    executeStream(request: CanonicalRequest, sink: ChunkSink): void
}

class DefaultExecutionEngine implements ExecutionEngine {
    // 依存（コンストラクタ注入）
    promptEngine: PromptEngine
    cacheEngine: CacheEngine
    capabilityResolver: CapabilityResolver
    routingEngine: RoutingEngine
    quotaManager: QuotaManager
    attemptExecutor: AttemptExecutor
    fallbackEngine: FallbackEngine
    responseMapper: ResponseMapper
    costEngine: CostEngine
    conversationManager: ConversationManager
    eventPublisher: DomainEventPublisher

    execute(req):
        publish(RequestReceived)
        prompt  = promptEngine.process(req)
        cached  = cacheEngine.lookup(req, prompt)
        if cached != null: return cached.withFlag()
        chain   = routingEngine.route(toRoutingRequest(req))
        quotaManager.checkAndReserve(req, prompt.estimatedTokens)
        publish(RequestStarted)
        result  = fallbackEngine.executeWithChain(chain, prompt, req)
        resp    = responseMapper.normalize(result)
        costEngine.record(resp)          // 非同期
        conversationManager.appendTurn(req, resp)  // 指定時
        cacheEngine.store(req, prompt, resp)
        publish(RequestCompleted)
        return resp
}
```

### 3.3.5 Retry / Fallback / Circuit Breaker（apap-execution）

```
interface RetryStrategy {            // Strategy（差替点）
    nextDelay(attempt: Int, error: NormalizedError, retryAfter: Duration?): Duration?
    // null = リトライしない
}
class ExponentialBackoffJitterStrategy implements RetryStrategy  // 既定

interface CircuitBreaker {
    tryAcquire(key: CbKey): Permit    // 拒否時 CircuitOpenException
    recordSuccess(key) / recordFailure(key, error)
    state(key): CbState               // CLOSED|OPEN|HALF_OPEN
}

class AttemptExecutor {   // 1候補への試行（Retry内包）
    execute(candidate, prompt, req): AttemptResult
        loop attempt = 1..maxAttempts:
            permit = circuitBreaker.tryAcquire(candidate.key)
            rateLimiter.acquire(candidate.provider, req.tenant)
            adapterReq = requestMapper.map(prompt, candidate, req)
            try:
                res = adapter.execute(adapterReq) within budget
                circuitBreaker.recordSuccess; return Success(res)
            catch e:
                circuitBreaker.recordFailure(e)
                delay = retryStrategy.nextDelay(attempt, e, e.retryAfter)
                if delay == null or budget.remaining < delay: return Failure(e)
                publish(RetryExecuted); sleep(delay)
}

class FallbackEngine {
    executeWithChain(chain, prompt, req): AttemptResult
        for candidate in chain:
            if circuitBreaker.state(candidate.key) == OPEN: continue
            adjustedPrompt = contextManager.refit(prompt, candidate.model)
            result = attemptExecutor.execute(candidate, adjustedPrompt, req)
            if result.isSuccess: return result
            if !result.error.fallbackable: return result
            publish(FallbackExecuted(from, next, reason))
        publish(RequestFailed); return lastResult
}
```

## 3.9 Adapter（パターンとしての適用）

## 3.11 Observer（イベント購読構成）

| Publisher | Event | Subscriber |
|---|---|---|
| Execution Engine | RequestCompleted / RequestFailed | Audit Engine, Cost Engine, Usage Read Model, Monitoring |
| Fallback / Retry | FallbackExecuted / RetryExecuted | Monitoring, Audit |
| Provider Manager | Provider*（登録/有効化/無効化） | Routing Engine（候補キャッシュ更新）, Audit |
| Model Manager | Model* / AliasChanged | Routing Engine, Cache Engine（Alias無効化）, Audit |
| Health Monitor | ProviderHealthChanged | Routing Engine, Alerting |
| Circuit Breaker | CircuitBreakerStateChanged | Monitoring, Alerting |
| Cost Engine | CostThresholdExceeded | Alerting, Routing Engine（Policy発動） |

実装: プロセス内は同期Dispatcher + 外部Event Bus（at-least-once）への非同期転送。購読側は冪等に実装（eventIdで重複排除）。

## 3.12 Command（パターン適用）

- Admin操作は Command オブジェクト（`RegisterProviderCommand` 等）として表現し、検証→実行→イベント記録を統一パイプラインで処理。Event Sourcing対象Aggregateはコマンドハンドラが `decide(state, command) → events[]` の純関数形式。
- Batchジョブは `BatchCommand` をキューへ投入し、Schedulerが実行（再実行安全）。

## 3.13 State（パターン適用）

| 対象 | 状態 | 実装 |

## 3.14 Policy（パターン適用）

```
interface Policy {
    policyId, scope: PolicyScope    // PLATFORM|TENANT|WORKFLOW|USER
    rules: List<PolicyRule>
}
class PolicyRule {
    effect: ALLOW | DENY
    target: { providers?, models?, capabilities?, regions? }
    condition: Expression?          // 例: cost.estimated > 0.05, time.window
    override: { weights?, fallbackDepth?, cacheTtl?, retryMax? }
}
// 評価: PLATFORM→TENANT→WORKFLOW→USERの順にマージ。
// DENYは累積（下位で解除不可）。overrideは後勝ち。
```

## 3.15 Dependency Injection構成

- **方式**: コンストラクタ注入のみ（フィールド注入禁止）。コンテナはコンポジションルート（`config/`）でのみ使用し、Domain層はコンテナ非依存。
- **スコープ**: 全EngineはSingleton。リクエスト状態は `ExecutionContext` オブジェクトとして引数伝播（ThreadLocal/暗黙コンテキスト不使用。ストリーム・非同期でも安全）。
- **SPIバインド**: 設定ファイルで実装を宣言的に選択。

```
# application.yaml（例）
apap:
  routing.strategy: weighted-score      # RoutingStrategy実装名
  retry.strategy: exp-backoff-jitter
  cache.store: distributed-kvs
  secret.store: vault-compatible
  compaction.strategy: truncate-oldest
  plugin.dir: /opt/apap/plugins
  plugin.signature.required: true
```

- **Pluginロード**: Plugin Managerが分離クラスローダ/プロセスでロードし、`ProviderAdapter` 実装をレジストリへ登録。コアのDIコンテナへは参加させない（隔離、NFR-SEC-004 / FR-SEC-005）。
- **テスト構成**: 全PortにIn-Memory実装を用意し、UseCase単体テストはInfrastructure不要で実行可能。
