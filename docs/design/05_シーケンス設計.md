## 5.1 Chat（同期）

```plantuml
@startuml seq_chat
autonumber
participant "利用システム" as App
participant "AI Gateway" as GW
participant "Prompt Engine" as PE
participant "Cache Engine" as CA
participant "Routing Engine" as RT
participant "Quota Manager" as QT
participant "Execution Engine" as EX
participant "Circuit Breaker" as CB
participant "Rate Limiter" as RL
participant "Request/Response Mapper" as MP
participant "Provider Adapter" as AD
participant "AI Provider" as PV
participant "Event Bus" as EV

App -> GW : POST /v1/chat (Capability=chat)
GW -> GW : トークン検証(CIAP)/tenant解決/RequestID付与
GW -> EV : RequestReceived
GW -> PE : process(CanonicalRequest)
PE -> PE : Validation → Optimization → Rendering
PE --> GW : ProcessedPrompt
GW -> CA : lookup(冪等キー/Responseキー)
CA --> GW : miss
GW -> RT : route(RoutingRequest)
RT -> RT : 候補抽出→フィルタ→スコア→Chain確定
RT --> GW : FallbackChain [c1, c2, c3]
GW -> QT : checkAndReserve(推定トークン)
QT --> GW : Reservation
GW -> EX : execute(chain, prompt)
EX -> EV : RequestStarted
EX -> CB : tryAcquire(c1)
CB --> EX : Permit
EX -> RL : acquire(provider, tenant)
RL --> EX : Permit
EX -> MP : map → AdapterRequest
EX -> AD : execute(AdapterRequest)
AD -> PV : Provider固有API呼出
PV --> AD : Provider固有応答
AD --> EX : AdapterResponse
EX -> CB : recordSuccess(c1)
EX -> MP : normalize → CanonicalResponse
MP --> EX : CanonicalResponse
EX -> CA : store(response)
EX -> QT : commit(実Usage)
EX -> EV : RequestCompleted(usage, cost)
EX --> GW : CanonicalResponse
GW --> App : 200 OK (共通Response)
note right of EV
  非同期購読: Audit Engine / Cost Engine /
  Usage Read Model / Monitoring
end note
@enduml
```

```plantuml
@startuml seq_embedding
autonumber

participant "Routing Engine" as RT

GW -> GW : 検証 / inputs分割判定(Adapter最大batch長)

  EX -> AD : execute(embedding chunk)

EX -> CA : store(入力毎に個別保存)
EX --> GW : vectors(700)
GW -> GW : hit分とマージ(入力順を復元)
GW --> App : 200 OK {vectors[1000], usage}
@enduml
```

## 5.3 Streaming

```plantuml
@startuml seq_streaming
autonumber
participant "利用システム" as App
participant "AI Gateway" as GW
participant "Execution Engine" as EX
participant "Streaming Engine" as SE
participant "Provider Adapter" as AD
participant "AI Provider" as PV
participant "Event Bus" as EV

App -> GW : POST /v1/chat (stream=true, SSE)
GW -> EX : executeStream(request, sink)
EX -> EX : Prompt/Routing/Quota (5.1と同一)
EX -> AD : executeStream(AdapterRequest)
AD -> PV : ストリーム接続
PV --> AD : provider chunk...
AD --> SE : AdapterChunk (pull: next())
SE -> SE : 正規化 (CONTENT_DELTA / TOOL_CALL_DELTA)
SE --> GW : StreamChunk
GW --> App : SSE: message_start
loop 応答生成中
  PV --> AD : provider chunk
  AD --> SE : AdapterChunk
  SE --> GW : StreamChunk(content_delta)
  GW --> App : SSE: content_delta
  alt クライアント送信バッファ超過
    SE -> AD : 読取一時停止(バックプレッシャ)
  end
end
PV --> AD : 終端(+usage)
SE -> SE : Usage確定
SE --> GW : StreamChunk(usage) + message_end
GW --> App : SSE: usage, message_end
SE -> EV : RequestCompleted
alt クライアント切断検知
  GW -> SE : cancel()
  SE -> AD : cancel()
  AD -> PV : 中断
  SE -> EV : RequestCompleted(finish=CANCELLED, 受信済usage)
end
@enduml
```

@startuml seq_tool_calling

AD -> PV : 結果返信
PV --> AD : 最終応答
AD --> EX : AdapterResponse

## 5.6 Fallback

```plantuml
@startuml seq_fallback
autonumber
participant "Execution Engine" as EX
participant "Fallback Engine" as FB
participant "Attempt Executor" as AT
participant "Context Manager" as CM
participant "Circuit Breaker" as CB
participant "Adapter A (c1)" as A1
participant "Adapter B (c2)" as A2
participant "Event Bus" as EV

EX -> FB : executeWithChain([c1, c2, c3], prompt)
FB -> CB : state(c1)?
CB --> FB : CLOSED
FB -> AT : execute(c1, prompt)
AT -> A1 : execute
A1 --> AT : AdapterException(PROVIDER_UNAVAILABLE)
AT -> AT : ErrorClassification → retry不可/fallback可
AT --> FB : Failure(fallbackable=true)
FB -> EV : FallbackExecuted{from=c1, to=c2,\n reason=PROVIDER_UNAVAILABLE}
FB -> FB : タイムアウト予算残 > c2のp50? → 続行
FB -> CB : state(c2)?
CB --> FB : CLOSED
FB -> CM : refit(prompt, c2.model)
note right : c2のcontext window/形式制約に\n合わせてPromptを再圧縮
CM --> FB : adjustedPrompt
FB -> AT : execute(c2, adjustedPrompt)
AT -> A2 : execute
A2 --> AT : AdapterResponse(成功)
AT --> FB : Success
FB --> EX : AttemptResult(provider=B)
alt 全候補失敗
  FB -> EV : RequestFailed{attempts, fallbacks}
  FB --> EX : Failure(最後のNormalizedError)
end
@enduml
```

## 5.7 Retry

```plantuml
@startuml seq_retry
autonumber
participant "Attempt Executor" as AT
participant "Retry Strategy" as RS
participant "Circuit Breaker" as CB
participant "Rate Limiter" as RL
participant "Provider Adapter" as AD
participant "Event Bus" as EV

AT -> CB : tryAcquire
CB --> AT : Permit
AT -> RL : acquire
RL --> AT : Permit
AT -> AD : execute (attempt=1)
AD --> AT : AdapterException(TRANSIENT: 503)
AT -> CB : recordFailure
AT -> RS : nextDelay(attempt=1, TRANSIENT, retryAfter=null)
RS --> AT : 217ms (200ms×2^0 + full jitter)
AT -> AT : 予算残確認(残 > 217ms) → 待機
AT -> EV : RetryExecuted{attempt=1}
AT -> AD : execute (attempt=2)
AD --> AT : AdapterException(RATE_LIMITED, retryAfter=2s)
AT -> RS : nextDelay(attempt=2, RATE_LIMITED, 2s)
RS --> AT : 2000ms (Retry-After優先)
AT -> EV : RetryExecuted{attempt=2}
AT -> AD : execute (attempt=3)
AD --> AT : AdapterResponse(成功)
AT -> CB : recordSuccess
alt attempt=3も失敗 (maxAttempts=3到達)
  AT --> AT : Failure返却 → Fallback Engineへ移行
end
@enduml
```

## 5.8 Provider切替（Alias切替によるModel/Provider移行）

```plantuml
@startuml seq_provider_switch
autonumber
actor "運用者" as Op
participant "Admin API" as AD
participant "Model Manager" as MM
participant "Event Bus" as EV
participant "Routing Engine" as RT
participant "Cache Engine" as CA
participant "利用システム" as App
participant "AI Gateway" as GW

Op -> AD : PUT /admin/v1/aliases/chat-standard\n{targets:[{model_new,10},{model_old,90}]}
AD -> MM : assignAlias(canary 10%)
MM -> MM : 検証: 両ModelがACTIVE/TESTING, weight合計=100
MM -> EV : AliasChanged{old, new}
EV -> RT : 購読 → 候補キャッシュ更新
EV -> CA : 購読 → Alias配下のResponse Cache無効化
AD --> Op : 200 OK
App -> GW : POST /v1/chat {model_alias: "chat-standard"}
GW -> RT : route
RT -> RT : CanaryResolution: hash(requestId)%100 < 10\n→ model_new / それ以外 → model_old
RT --> GW : 選択されたModelでChain構築
note over Op : メトリクス確認後、段階的にweight変更\n10% → 50% → 100%
Op -> AD : PUT .../aliases/chat-standard {[{model_new,100}]}
AD -> MM : assignAlias(100%)
MM -> EV : AliasChanged
note over App : 利用側はAlias名のみ指定のため変更ゼロ
@enduml
```

## 5.10 Health Check

```plantuml
@startuml seq_health_check
autonumber
participant "Scheduler" as SC
participant "Provider Manager" as PM
participant "Adapter A" as AD
participant "Health Store" as HS
participant "Event Bus" as EV
participant "Routing Engine" as RT
participant "Monitoring Engine" as MO

SC -> SC : リーダー選出済ノードのみ実行(30秒周期)
SC -> PM : activeProviders()
PM --> SC : [Provider A, B, ...]
loop Provider毎(並列)
  SC -> AD : healthCheck()
  AD -> AD : 軽量疎通 + 認証検証
  AD --> SC : HealthResult{status, latency}
  SC -> HS : 記録(probe結果)
  HS -> HS : パッシブヘルス(実トラフィック成功率)と合成
  alt 判定変化 (例: UP → DOWN, 連続3回失敗)
    HS -> EV : ProviderHealthChanged{A, UP→DOWN}
    EV -> RT : 購読 → 候補から即時除外
    EV -> MO : 購読 → アラート発火
  end
end
alt Adapterがタイムアウト(5s)
  SC -> HS : probe失敗として記録
end
@enduml
```
