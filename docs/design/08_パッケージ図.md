# 8. パッケージ図

AI Provider Abstraction Platform（APAP）設計書 第8章（PlantUML）

---

```plantuml
@startuml package_apap
skinparam packageStyle rectangle

package "apap-api\n(公開契約)" as api {
  package "dto" {}
  package "error" {}
  package "openapi/protobuf" {}
}

package "apap-gateway\n(Presentation)" as gateway {
  package "rest" {}
  package "grpc" {}
  package "sse" {}
  package "authfilter" {}
}

package "apap-application\n(UseCase)" as application {
  package "command" {}
  package "query" {}
}

package "apap-domain\n(最内層・依存なし)" as domain {
  package "model\n(Entity/VO/Aggregate)" as dmodel {}
  package "event" as devent {}
  package "service\n(Domain Service)" as dservice {}
  package "port\n(Repository/SPI IF)" as dport {}
}

package "apap-execution" as execution {}
package "apap-routing" as routing {}
package "apap-prompt" as prompt {}
package "apap-context" as context {}
package "apap-provider" as provider {}
package "apap-plugin" as plugin {}
package "apap-cache" as cache {}
package "apap-cost" as cost {}
package "apap-observability" as observability {}

package "apap-adapter-spi\n(Adapter開発者向け)" as spi {}

package "apap-infrastructure" as infra {
  package "persistence" {}
  package "eventbus" {}
  package "secret" {}
  package "kvs" {}
}

package "adapters/*\n(Provider毎Plugin・独立配布)" as adapters {}

gateway ..> application
gateway ..> api
application ..> domain
execution ..> domain
routing ..> domain
prompt ..> domain
context ..> domain
provider ..> domain
plugin ..> domain
cache ..> domain
cost ..> domain
observability ..> domain
application ..> execution
application ..> routing
application ..> provider
execution ..> routing
execution ..> prompt
execution ..> context
execution ..> cache
execution ..> cost
spi ..> dmodel : 型参照のみ
adapters ..> spi : SPIのみに依存\n(コア非依存)
infra ..> dport : Port実装
plugin ..> spi : ロード契約

note bottom of domain
  依存規則(Clean Architecture):
  すべての依存は内向き(domainへ)。
  domainはいかなる外部にも依存しない。
end note
note bottom of adapters
  adapterはapap-adapter-spiのみ参照。
  コア変更なしで追加・差替可能。
end note
@enduml
```

**依存規則の要点**: `apap-domain` は依存ゼロの最内層。`adapters/*` は `apap-adapter-spi` のみに依存し、独立してビルド・配布・バージョニングされる（NFR-EXT-001 / NFR-MNT-001）。`apap-infrastructure` はDomainのPort（interface）を実装する側であり、依存性逆転が成立する。
