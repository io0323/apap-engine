# 9. 状態遷移図

AI Provider Abstraction Platform（APAP）設計書 第9章（PlantUML）

---

## 9.1 Provider状態遷移

```plantuml
@startuml state_provider
[*] --> REGISTERED : register
REGISTERED --> VALIDATING : validate開始
VALIDATING --> ACTIVE : 検証合格\n(Credential/疎通/Capability)
VALIDATING --> REGISTERED : 検証失敗
ACTIVE --> SUSPENDED : suspend\n(障害/手動)
SUSPENDED --> ACTIVE : resume\n(Health回復/手動)
ACTIVE --> DRAINING : drain指示
DRAINING --> DISABLED : 実行中リクエスト完遂\n(または排出タイムアウト300s)
DISABLED --> VALIDATING : 再有効化
DISABLED --> DELETED : delete(論理削除)
DELETED --> [*]
note right of DRAINING : 新規ルーティング対象外。\n実行中は完遂させる(FR-PRV-002)
note right of DELETED : 履歴・監査は保持
@enduml
```

## 9.2 Model状態遷移

```plantuml
@startuml state_model
[*] --> REGISTERED : register\n(手動/Discovery承認)
REGISTERED --> TESTING : テスト開始
TESTING --> ACTIVE : 検証合格・承認
TESTING --> REGISTERED : 差戻し
ACTIVE --> DEPRECATED : deprecate\n(後継Model移行開始)
DEPRECATED --> ACTIVE : 復帰
DEPRECATED --> RETIRED : Alias参照ゼロ確認後\nretire
RETIRED --> [*]
note right of TESTING : Canary対象としてのみ\nルーティング可
note right of DEPRECATED : 既存Alias参照のみ許可\n新規Alias付与不可
@enduml
```

## 9.3 Circuit Breaker状態遷移

```plantuml
@startuml state_circuit_breaker
[*] --> CLOSED
CLOSED --> OPEN : 30sウィンドウで\nreq>=10 かつ 失敗率>=50%
OPEN --> HALF_OPEN : open時間経過\n(30s×2^n, 上限600s)
HALF_OPEN --> CLOSED : 3連続成功
HALF_OPEN --> OPEN : 1失敗
note right of OPEN : tryAcquireは即時拒否\n→ Fallback対象
note right of HALF_OPEN : 最大3並行まで試行許可
note bottom of CLOSED : 状態は共有ストアで\n全ノード共有(2.13)
@enduml
```

## 9.4 リクエストライフサイクル

```plantuml
@startuml state_request
[*] --> RECEIVED : Gateway受信
RECEIVED --> VALIDATED : 認証/検証OK
RECEIVED --> REJECTED : 認証/検証NG\n(4xx返却)
VALIDATED --> CACHED_HIT : Cache hit
CACHED_HIT --> COMPLETED
VALIDATED --> ROUTED : Chain確定
ROUTED --> EXECUTING : 候補実行開始
EXECUTING --> RETRYING : リトライ可能エラー
RETRYING --> EXECUTING : バックオフ後再試行
EXECUTING --> FALLING_BACK : 候補内試行尽き\nかつfallback可
FALLING_BACK --> EXECUTING : 次候補で実行
EXECUTING --> COMPLETED : 成功
EXECUTING --> FAILED : fallback不可エラー
FALLING_BACK --> FAILED : 全候補失敗/予算切れ
EXECUTING --> CANCELLED : クライアント切断/cancel
COMPLETED --> [*] : RequestCompleted発火
FAILED --> [*] : RequestFailed発火
CANCELLED --> [*]
REJECTED --> [*]
@enduml
```

## 9.5 Batch Job状態遷移

```plantuml
@startuml state_batch_job
[*] --> SUBMITTED : submit
SUBMITTED --> QUEUED : 受理・検証OK
SUBMITTED --> FAILED : 検証NG
QUEUED --> RUNNING : Schedulerが実行開始
RUNNING --> RUNNING : item処理\n(進捗更新)
RUNNING --> COMPLETED : 全item完了
RUNNING --> FAILED : 致命的エラー\n(部分結果は保持)
QUEUED --> CANCELLED : cancel
RUNNING --> CANCELLED : cancel\n(実行中itemは完遂)
COMPLETED --> [*] : 結果保持期間(既定7日)後に破棄
FAILED --> [*]
CANCELLED --> [*]
@enduml
```

## 9.6 Streamセッション状態遷移

```plantuml
@startuml state_stream
[*] --> OPENING : executeStream
OPENING --> ACTIVE : 初回チャンク送出
OPENING --> ABORTED : 初回チャンク前失敗\n(→Fallback対象)
ACTIVE --> ACTIVE : chunk中継/heartbeat(15s)
ACTIVE --> DRAINING : Provider終端受信
DRAINING --> CLOSED : usage確定+message_end送出
ACTIVE --> ABORTED : ストリーム中エラー\n(errorチャンク送出, Fallback不可)
ACTIVE --> ABORTED : クライアント切断\n(Providerへcancel伝播)
ACTIVE --> ABORTED : アイドル60s/全体300s超過
CLOSED --> [*]
ABORTED --> [*] : 部分usageで確定・監査記録
@enduml
```

## 9.7 Credential状態遷移

```plantuml
@startuml state_credential
[*] --> STANDBY : 新Credential登録
STANDBY --> ACTIVE : 検証合格→昇格\n(旧ACTIVEはREVOKED_PENDINGへ)
ACTIVE --> REVOKED_PENDING : 新世代昇格
REVOKED_PENDING --> REVOKED : 猶予期間(既定24h)経過\nProvider側でも失効
STANDBY --> REVOKED : 検証失敗
REVOKED --> [*]
note right of ACTIVE : ACTIVEは常に1世代のみ\n(4.3.1不変条件)
@enduml
```
