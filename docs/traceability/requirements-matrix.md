# トレーサビリティマトリクス

docs/design/01_要件定義.md の機能要件（FR-*）・非機能要件（NFR-*）と、実装クラス・テストクラスの対応表。
01_CLAUDE.md「トレーサビリティ」規約に従い、機能実装時に該当行の「実装クラス」「テストクラス」「状態」を更新すること。

## 状態の判定基準（P11で明文化）

状態は **実装済 / 部分実装 / 未実装 / 対象外** のいずれか。P11以前に使っていた「実装中」は、
「Domain層だけ揃った」状態と「E2Eで動く」状態を区別できず、**実装されているが本番配線から
到達できない**という本プロジェクトで繰り返し発生した問題（AuditEngine・MetricsEngine・
ZeroCostEstimator等）を隠してしまうため廃止した。

| 状態 | 判定基準（3条件すべてを満たすかで判定する） |
|---|---|
| **実装済** | (1) 本番の配線（`ApapEngineBuilder.build()` または Gateway 起動）から到達する経路が存在する **かつ** (2) その経路を通るテストが存在して緑である **かつ** (3) 要件文の記述をすべて満たす |
| **部分実装** | 実装は存在するが (1)(2)(3) のいずれかを欠く。**欠けている条件と残作業を必ず状態欄に書く** |
| **未実装** | 要件を満たす実装クラスが存在しない |
| **対象外** | 本リポジトリの成果物では充足を判定できない（インフラ設定・運用実績・外部システム側の責務）。理由を状態欄に書く |

**「動作している」と「検証されている」を区別する**: (1)だけを満たし(2)を欠く場合は実装済とせず、
「到達可能だがテストが無い」と明記して部分実装とする。逆に単体テストが緑でも(1)を欠く場合
——本番配線のどこからも生成されないクラス——は部分実装であり、実装済ではない。

`P11-Fn` / `P11-Dn` は `docs/verification-report.md` の指摘番号。クラス名はモジュール内での相対参照。
